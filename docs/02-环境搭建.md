
它依次调用：

| 脚本 | 作用 |
|---|---|
| `install-wsl-openems.ps1` | Windows 侧：启用 WSL + 装 Ubuntu（需管理员） |

## 避坑记录

### FEniCSx 不要走原生 Windows

两条死结（都实测确认过）：

| 问题 | 说明 |
|---|---|
| 缺 `petsc4py` | conda-forge 的 **win-64 没有该包**，PyPI 也**没有 Windows 轮子**（HTTP 404） |
| 缺 MSVC | ffcx 用 CFFI 做 JIT，Windows 上只认 `cl.exe`，MinGW 顶不上 |

`fenics-dolfinx` 在 **PyPI 上根本不存在**，只能从 conda-forge 或 FEniCS 的 apt PPA 装。
Linux 上一次就过。

### ffcx 与 ufl 的版本配对

conda-forge 上两个 ffcx 构建对应不同的 ufl：

```
fenics-ffcx=0.11.0=pyhc104ebe_0  需要 fenics-ufl 2026.1.*
fenics-ffcx=0.11.0=pyh4a40500_0  需要 fenics-ufl 2025.2.*
```

配错会报 `Can not map ... to a basix type`（`cellname` 属性/方法之争）。

### GitHub 直连不稳

| 资源 | 直连速度 | 解决 |
|---|---|---|
| WSL 安装包（367MB） | 25 KB/s | gh-proxy 镜像 + 8 连接并行分块 → 4 MB/s |
| openEMS 源码 | RPC failed / early EOF | git `insteadOf` 重写到 gh-proxy |

### PowerShell 脚本必须带 UTF-8 BOM

Windows PowerShell 5.1 不把无 BOM 的 UTF-8 当 UTF-8 读，
中文字符会截断字符串引号，脚本直接解析失败。`scripts\*.ps1` 都已加 BOM。
